# SPRING DRILL（仮）― ためて、ぶちぬけ。

ドリル機体で地底へ掘り進むハイパーカジュアル・アクションの**ステージクリア型プロトタイプ（3ステージ）**。

技術スタック: **TypeScript + HTML5 Canvas + Vite**（外部アセット・外部ライブラリゼロ。音はWeb Audio合成、絵はすべてコード描画）。iOS へは Capacitor で書き出す（`docs/ios-setup.md`）。

> 旧プロトタイプ「秒針ヒーロー(Secondly)」からのピボット。コア基盤(ループ/シーン/入力/演出/音)は流用し、ゲーム本体を差し替えた。旧版はgit履歴(コミット `439aa33`)に残っている。

---

## USP（差別化要素）

1. **「ためて、一気にぶちぬく」緩急のリズム** ― 掘削系の定番「押しっぱなし」に対し、本作は長押しでバネを圧縮 → 離した瞬間に多層を貫通ダッシュ。岩盤の前でタメて、鉱脈ごと一직선にぶち抜くカタルシス。
2. **理不尽ゼロ設計** ― ダメージ源は静的な可視ハザードのみ（動く敵・時限攻撃・ランダム生成なし）。時間制限もなし（タイムはボーナス加点のみ）。失敗は100%操作に帰着する。
3. **ステージ設計×メタ進行が最初から結線** ― 文字列1行=地層1行のデータ駆動マップで、レベルデザインを無限に量産できる。鉱石コイン→アップグレード（ステージ間ショップ）の経済も雛形実装済み。

## 遊び方

| 操作 | 効果 |
| --- | --- |
| **横ドラッグ** | 機体の左右移動（土は削りながらゆっくり、空洞はスイスイ） |
| **長押し（指を止めて）** | バネ圧縮チャージ（Lv1/Lv2/MAX の3段階。機体は停止） |
| **離す** | 圧縮した分だけ下方向へ貫通ダッシュ |

- 通常時は自動でゆっくり掘り進む。岩や鉄骨の上では自動停止 → チャージして砕くか、横に迂回するかを選ぶ
- **ドラッグ操縦中はチャージが増えない**（誤爆ダッシュ防止）。ダッシュは Lv1=4行 / Lv2=7行 / MAX=11行（鉄骨はLv2以上）
- **ハザード**: 溶岩=壊せない。上に乗るのは安全だが**ダッシュで突っ込むとダメージ**。ガス=触れるとダメージ、ただし**ダッシュ中は無害に破壊できる**
- ティア不足で硬いタイルに当たっても**ノーダメージで停止**（ガキン）。罰は時間ロスだけ
- 最深部の**コア**に到達でステージクリア。HP0で失敗（コインの半分は持ち帰り）

## スコア

`貫通コンボ 30×n²（1ダッシュで壊した枚数n） + 鉱石50/ジェム250（ダッシュ中の取得は×2） + タイムボーナス max(0, めやす秒−クリア秒)×100 + 残HP×500`

## ステージ / メタ進行

- **1. やわらかい地層**（28m）: 土主体。単発の岩がダッシュを自然に教える
- **2. 鉄骨とマグマ**（40m）: 鉄骨梁は「土の迂回路」か「Lv2で貫通の近道」かの選択。ガス混じり鉱床の欲張りリスク
- **3. コアの間**（55m）: 岩10連の縦坑はMAXチャージの見せ場。蛇行する溶岩帯。コアは鉄骨ケース入り
- **ショップ**: ハイスピードバネ（チャージ時間短縮）/ アーマープレート（HP+1）。鉱石コインで購入
- セーブ: localStorage（`springdrill.save.v1`）にコイン・解放状況・ベスト・アップグレードを永続化

### 理不尽ゼロの設計ルール（`src/game/stages.ts` のdevバリデータで機械的に強制）

1. ダメージ源は静的タイルのみ・全ハザードは接触の数秒前から見える（ダッシュ最大11行 < 画面先読み約12行）
2. 全ステージ「無強化（Lv1ダッシュ+土の横掘り）だけでコア到達可能」をBFSで検証（アップグレードは常に近道であって必須にしない）
3. 溶岩行には安全列が2列以上あり、直上行の安全列と隣接（強制被弾なし）

## 開発・実行

```bash
npm install
npm run dev      # 開発サーバ（マウス操作可。←→=移動 / スペース=長押し）
npm run build    # 型チェック+本番ビルド（dist/）
```

iOS 書き出し（Mac上）: `docs/ios-setup.md` を参照。**先に本ブランチをcheckoutすること**（mainにはコードがない）。

## ディレクトリ構成

```
src/
  core/     ループ(固定タイムステップ)・シーン遷移・入力(押す/離す/横ドラッグ)・画面/DPR・数学・乱数
  game/     ★純ロジック(描画非依存)
    config.ts   全チューニング定数の一元管理 ※バランス調整はここだけ触る
    stages.ts   ステージデータ(1行=7文字の文字列マップ)+理不尽検出バリデータ ※レベル追加はここ
    machine.ts  機体: drilling(自動掘削)→charging(圧縮)→dashing(貫通)→hurt
    terrain.ts / world.ts / score.ts / save.ts
  render/   Canvas描画(layout=座標変換 / terrain=地層 / machine / hud / ui / fx)
  fx/       パーティクル(固定長プール)・ヒットストップ/画面シェイク
  audio/    Web Audio合成の効果音一式(ファイルなし)
  scenes/   タイトル / ステージ選択 / プレイ / リザルト / ショップ
```

## ステージの作り方

`src/game/stages.ts` の `rows` に1行7文字の文字列を並べるだけ:

```
.  土(自動掘削可)   _  空洞          R  岩(Lv1ダッシュで破壊)
S  鉄骨(Lv2以上)    o  鉱石(+1コイン) G  ジェム(+5コイン)
L  溶岩(ダッシュ突入でダメージ)      g  ガス(接触ダメージ/ダッシュなら無害破壊)
C  コア(到達でクリア)
```

devビルド起動時にバリデータが走り、到達不能・強制被弾などの違反は `console.error` で報告される。

## 検証（ヘッドレス環境）

devビルドでは `window.__drill`（`state()` / `warp(depth)` / `moveTo(col)` / `world`）が公開され、
Playwright から決定論的な検証ができる（掘削・貫通・被弾・クリア・セーブ・ショップ購入を自動テスト済み）。
